What the reviewers agreed on

The Enter label changing with width was flagged by 4 of 5 reviewers. The cramped wide card and the detail layout changing at each size were each flagged by 3. Two of the five big ideas, from the Visual and Layout reviewers, arrive at the same answer: fewer detail layouts.

Each reviewer's big idea

V One detail layout at every size

Today there are three detail designs: a narrow card at 120, a strip at 80, a header plus a repeated DOCS block at 60. One layout (a header, tabs that always include Overview, and sections that drop out as room runs out) would fix the indent drift, the wraps and the date mismatches in one place.

I The breadcrumb states the whole view

For example: Applied › Status: Applied · Track: SWE · "/eng" · newest first · 2/5. Today that state is spread over the chips, the search chip, the tab counts and toasts. One line answers "why am I seeing only 2 rows?" and still fits at 60 columns.

A One glyph per meaning, with a word wherever there is room

Each meaning gets a glyph nothing else uses (for example "due 9mo" or "now"), and the ASCII and no-colour modes are generated from that same table. Colour becomes a redundant extra cue, as WCAG 1.4.1 asks.

C A single vocabulary for stages, groups and documents

Rename the Applied screen so it no longer shares a name with a status. Make Closed mean Rejected plus Withdrawn everywhere. Use one document set and one meter. List every track in use, Unknown included.

R Two layouts, not three

Drop the 80x24 list-over-detail split. Use side by side when wide and full screen when narrow. This halves the cases where text can be clipped.

Where they converge: V and R both argue for fewer detail layouts. A full-screen detail at 80x24 and below, plus one section order at every size, would cover both ideas. It would also remove the wide-card, 60-column and 80x24 bugs above.

Recommendation

  1. Fix now, in one pass:
    • the toast row's status label;
    • a visible strip focus;
    • the status filter in the breadcrumb;
    • the Menu pop-up clearance;
    • pinning ctrl+s and u undo while they apply;
    • a wider card at 120 columns (about 44), so the DOCS count and m move stay on their lines;
    • a "↓ N more" cue and no tab wrap at 60 columns;
    • an inline error for a required field;
    • one Enter label;
    • hiding the global keys while typing;
    • a lighter hint colour on the selection bar;
    • even chip spacing.
  2. File as issues: the unreachable Unknown track; the Settings save model; and the bigger ideas: one glyph table (A), a single vocabulary (C), and two detail layouts instead of three (V + R).
  3. The breadcrumb as a full statement of the view (I) is worth a spike. It would replace the strip-focus and status-filter fixes with one design.
