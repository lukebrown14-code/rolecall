Claude across the whole job search

How rolecall can use Claude to find the right roles, write an honest CV and cover letter that recruiters can find, and help with applying and everything after. Three research agents each covered one stage, and this page joins their findings into one plan that fits rolecall's existing rules.

The one rule every idea below follows: Claude does the legwork and writes files; the Owner decides. Claude never invents a fact, never submits an application, never sends an email, and never moves a Status on its own.

The journey, end to end

Each stage names the Claude tool that does the work. Arrows run left to right; each lane hands its files to the next.

1 · Find the right roles

  1. Sweep the Sourcessweep.py pulls from ATS APIs (Greenhouse, Ashby, Lever…)
  2. Read job-alert emailsGmail connector covers Seek and LinkedIn without crawling them
  3. Cheap triageHaiku subagent keeps or drops each candidate, giving a reason
  4. Judge & create LeadsOpus via find-jobs → meta.py create + jd.md
  5. Score Fitassess-fit → fit.md, requirements.json

2 · Write the documents

  1. Extract requirementsschema-checked must-haves and nice-to-haves
  2. Match against the Profileevidence.md traces every claim to a Profile line
  3. Draftprepare-documents; a hook checks each write as it lands
  4. Independent reviewrecruiter and fact-checker subagents → review.md
  5. Build & ATS checkbuild.py gates → PDFs → Ready

3 · Apply and follow through

  1. Assisted submitClaude in Chrome fills the form and uploads the PDFs, then stops
  2. Owner clicks SubmitTUI confirms → Applied, sent/ frozen
  3. Reply triageGmail → proposal.yml, which the Owner accepts with y
  4. Follow-ups & interviewsscheduled drafts; Calendar → interview.md
  5. Offersoffer.md comparison plus a negotiation draft
Lead→Draft→Applied→Interviewing→Offer  · Only the TUI and the Owner move a Status after Lead (the one automatic move, Lead → Draft, stays)

Integration architecture

Three tiers, one rule: every tier writes files into the Workspace. This keeps ADR-0003 (files are the only contract) and ADR-0005 (Owner data stays local).

TIER 1 · EXISTS (v0.2)
The TUI suspends and runs the skill in the Owner's terminal. Claude can ask questions, drive Chrome and use connectors. Used for anything that writes documents or acts on the web.
TIER 2 · NEW · amends ADR-0003
claude -p with structured JSON output, started by the TUI (RunCaptured), a Desktop local scheduled task or launchd. It writes drafts and proposal.yml only, never documents.
TIER 3 · CONNECTORS
Gmail, Calendar and Chrome reached through either tier. Remote Control on a phone is a window onto tier 1, not a new data path. Cloud routines don't fit: they need a GitHub remote.

Guardrails

Always

  • Every document claim traces to a Profile line; build.py stays the final gate.
  • The Owner clicks Submit, accept and send.
  • One Application per run.
  • Screening answers come only from the Profile and the Owner.
  • Disclose AI use where a form asks.
  • Cap budget and new Leads on every unattended run.

Never

  • Auto-apply, mass apply or “spray and pray”.
  • Solve or bypass CAPTCHAs, or touch identity or payment steps.
  • Scrape LinkedIn with a bot or browser plugin (User Agreement §8.2).
  • Send Owner data to a hosted page (Artifacts, Docs) or a cloud routine without a new opt-in ADR.
  • Keyword-stuff to “beat the ATS”: auto-rejection is mostly a myth, and recruiters search by the ad's skills.

Before you start

  • The Gmail and Google Calendar connectors aren't authorised in this environment yet. Connect them in claude.ai connector settings before prototyping FIND·4, APPLY·3, APPLY·4 or APPLY·5.
  • Claude in Chrome needs a direct Anthropic plan login, not an API key, and a project's settings can't turn it on.
  • Unverified items to check while prototyping: Workable endpoint SmartRecruiters key Seek terms connector tool names in Claude Code Calendar write scope push reliability Read tool on PDFs.
